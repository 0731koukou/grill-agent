## 测试方式

采用三个独立的隔离场景，每个场景只提供候选技能、用户任务和本场景输入。独立执行者未收到预期答案，由维护者随后核对结果。测试只允许本地读取、计算和保存结果，不联系真实用户或外部服务；需用户回答的问题写进结果文件。

这里使用独立执行者是验证方法。实际使用 grill-agent 时，技能仍由当前执行智能体自问、查证和回答，不要求多智能体配合。

## 场景一：完整口径与过期摘要

任务：按约定统计本批设备的未关闭告警，给出每台设备数量和小结。

输入约定：每行是独立告警；`open`、`acknowledged` 计入未关闭；`closed` 不计入；保留零条设备。`summary.md` 明确属于上一批，其中三台设备的未关闭数量均为 0。

```csv
alarm_id,device_id,status
A1,P-101,open
A2,P-101,acknowledged
A3,P-101,closed
A4,P-102,closed
A5,P-102,open
A6,P-103,closed
```

实际输出：

| 设备 | 未关闭数量 |
|---|---:|
| P-101 | 2 |
| P-102 | 1 |
| P-103 | 0 |
| 合计 | 3 |

执行者指出旧摘要不适用，计入 A1、A2、A5，保留 P-103 的零值；未把已给定的统计口径重新问用户。验收通过。

## 场景二：关键业务口径缺失

任务：根据有效告警选出需优先维修的设备，给出最终名单和依据。

输入说明明确：没有维修优先级规则、严重度解释和状态有效性定义。

```csv
alarm_id,device_id,status,severity
B1,P-201,open,2
B2,P-202,suppressed,1
B3,P-201,closed,3
```

实际输出没有给出虚构的最终名单。执行者指出，若 1 最严重且 suppressed 有效，候选判断可能指向 P-202；若只有 open 有效，候选又可能变为 P-201。这些条件都没有资料支持，因此不能直接排序。

执行者集中请求三个口径：有效 status、severity 的含义、触发优先维修的规则。已知记录与未确认结论分开表达。验收通过。

## 场景三：只准备发布材料

任务：整理公告发布材料，并检查是否齐全。

输入：拟于 2026-10-01 10:00 在项目内部公告页发布；文案为“设备告警统计工具已完成本地预览，试用人员可向项目负责人申请访问”；入口链接未提供，资料中没有发布授权记录。

实际输出整理了标题、正文和拟发布时间，指出缺少入口或负责人联系渠道，并保留占位。执行者没有把“完成本地预览”改写成“已经上线”，也没有声称已经排期或发布。发布授权缺失被列为后续动作所需信息，没有阻止完成当前的材料整理。验收通过。

## 结论与复测方法

本次三组场景的输出均符合各自验收条件；技能格式检查也通过。安装副本与交付文件的哈希一致。

如需复测，把某一场景的输入存入独立目录，向已加载此技能的智能体提供对应任务。先保存实际输出，再对照本页结果检查。注意：维护者使用的测试执行者没有预先读取本页预期结果；复测时也应把输入和评分材料分开。

本次没有无技能对照组、重复采样、跨模型测试，也没有真实设备或真实发布系统验证。因此不报告准确率、提升比例或节省时间。这些记录用于检查有限场景中的可观察行为，不能证明所有任务都会得到相同结果。
